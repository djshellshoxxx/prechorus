# PreChorus feature audit and completion — 2026-10-14

Scope: `djshellshoxxx/prechorus`. Baseline: `main` @ `af8ae99` plus the unmerged PR #4 branch (`claude/project-build-status-ukn1ju`, merged into this branch without conflicts).
This report covers the audit, what was fixed or built in response, what was verified and how, and what remains (all of it needs owner input).

## 1. Method

1. Read `README.md`, `docs/PRECHORUS_SPEC.md`, `docs/FEATURE_SPECS.md`, `ROADMAP.md`, `docs/standards/CDL_PLUGIN_BASELINE.md`, release notes, workflows and every line of `Source/`.
2. Inventory: GitHub issues (0), pull requests (#1–#3 closed/merged, **#4 open**: "Post-beta batch 1"), branches (`main`, #4's branch, this branch).
3. Traced each promised feature from UI handler → processor → render/audio path → state → tests, looking for no-op wiring, stubs, spec divergence and doc drift.
4. Built and ran everything that can run on Linux (commands in §5). Windows cannot be built in this environment; it is built by GitHub Actions (§6).

## 4. Deviations from `FEATURE_SPECS.md` (deliberate)

* **V1 stems**: outputs are *Swarm*, *Hit* and *Dry* (they sum exactly to the main output) rather than Wet/Dry/pre-FX, because only one rendered buffer exists and a pre-FX stem would need a second render.
* **U3 Next bar / Loop end** schedule the swarm early instead of reporting latency, so they never use PDC. Tempo is assumed constant over the swell.
* **F1** history strip is covered by undo/redo; **U7** font scaling is covered by window scaling (60–200 %).
* **F2 morph** re-renders at ≤ ~8 Hz from the message thread.
* **V2** has no MP3 (JUCE cannot encode it) and no OGG (needs a build flag).

```
clap-validator validate PreChorus.clap  # 21 tests run, 18 passed, 0 failed, 3 skipped
python3 tools/gen_param_reference.py --check
```

ASan/UBSan and TSan are run by `build-linux.yml` on every PR.

## 6. Windows build

Windows cannot be compiled here. The *Build Windows* workflow (MSVC, static runtime) configures, builds VST3/CLAP/Standalone and the test binary, runs `ctest`, packages the installer, portable zip, VST3 zip and CLAP zip, and uploads them (with SHA-256 sums) as the artifact **PreChorus-Windows-<run number>** on the pull-request run. No release is published; tagging `v*` (or running *Release*) still publishes to GitHub Releases.
The Windows binaries have not been hand-tested in a DAW by the author of this change.

## 7. Known limitations and risks

* Hosts differ in whether they forward CC to effects, enable sidechain/stem buses, or report loop points; the automatic target modes and MIDI learn are tested against a mock host only.
* The formant shifter costs about a second of background render time per minute of source (it only runs when FORMANT ≠ 0).
* Keyboard/screen-reader support is implemented through JUCE accessibility metadata and has not been exercised with a real screen reader.
* Embedded audio stays capped at roughly 30 MB per project.
